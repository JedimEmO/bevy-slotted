# What Minecraft mods actually build with their UI freedom

A catalogue of mod UIs, organised by category, with the primitives each one needs. The goal is to derive the widget set and extension points a Bevy plugin stack must expose so that "modders" of a Minecraft-style game get the same creative room.

## 1. Machine and storage GUIs

The bulk of modded UI is the `ContainerScreen`: a 176x166 nine-sliced panel, a slot grid, and whatever the mod bolts onto it. Observed patterns:

- **Thermal Expansion** (https://www.curseforge.com/minecraft/mc-mods/thermal-expansion). Machines have a row of side tabs that slide out on click: augments (extra slots appear inside the tab), redstone control (cycling button ignore/low/high), side configuration (a 3x3 mini-cube where each face cycles input/output/none, coloured), security, and an energy bar with a mB/RF tooltip. Needs: sliding tab widget that grows its bounds and hosts child widgets, cycling icon button with per-state texture, face-config grid, vertical bar with fill fraction.
- **Mekanism** (https://www.curseforge.com/minecraft/mc-mods/mekanism). Side tabs on both edges (side config, transporter colour config, upgrades, security, redstone, chemical/gas dumping). Gas, fluid and infusion tanks render a tiled texture whose colour is tinted from the chemical registry; the energy bar is a masked sprite. Transporter config uses a colour picker grid of 16 dye colours. Progress arrows are per-recipe-type. Needs: tiled-texture tank with tint and unit tooltip, colour swatch picker, masked directional progress sprite, warning icon overlays.
- **GregTech / GTCEu** (https://github.com/GregTechCEu/GregTech-Modern). Multiblock controller GUIs with a structure-status pane, several fluid tanks, multiple parallel progress bars, item and fluid filter slots (ghost items), text fields for numeric thresholds, and a "structure preview" rendered in JEI. GTCEu is built on LDLib, which is itself a component tree with an in-game UI editor. Needs: dynamic slot counts, text/number inputs, tooltip text blocks with formatted lists, embedded 3D block preview.
- **Create** (https://github.com/Creators-of-Create/Create). Mostly avoids container GUIs: Schematicannon has a themed screen with a progress "cannon" and toggle buttons; the Stock Keeper and Factory Gauge have search fields and category tabs. Tooltips are two-stage: "Hold [Shift] for summary" expands a colour-formatted description. Engineer's Goggles draw a HUD overlay next to the crosshair with stress, speed and per-block info (https://create.fandom.com/wiki/Pondering). Needs: hold-key tooltip expansion, world-anchored HUD text with item icons, non-rectangular themed frames.
- **Applied Energistics 2** (https://guide.appliedenergistics.org/1.20.1/items-blocks-machines/terminals). The ME Terminal is a virtual scrolling grid over thousands of stored stacks with a search box, sort mode buttons, view-cell filters, and a "terminal style" setting of small, tall or full height that recomputes the row count from window height. The crafting terminal adds a 3x3 grid, pattern encoding terminal toggles between crafting/processing and shows ghost item slots, the interface config has filter slots, and the Pattern Access Terminal groups rows by host machine. Needs: virtualised grid (render N visible rows from a large list, scrollbar), search field with hotkey focus, dynamic screen height, grouped rows with headers, ghost/phantom slots that accept a drag but hold no real item.
- **Refined Storage** (https://refinedmods.com/refined-storage/) mirrors AE2's grid and adds a grid-size option (stretch to window). **Storage Drawers** uses in-world quantity labels rather than a GUI. **Iron Chests / Expanded Storage** have 9x6 up to 12x9 grids; Expanded Storage offers a scrollable 108-slot view so the screen fits. Needs: slot grid with arbitrary dimensions, scroll-clipped slot region.
- **Sophisticated Backpacks / Storage** (https://www.curseforge.com/minecraft/mc-mods/sophisticated-backpacks). Upgrade tabs on the right edge open into sub-panels with their own filter slots and toggle rows; a settings tab has sub-tabs (memory slots, no-sort slots, item display); a sort button and sort-mode button sit above the grid. Upgrade tabs are "registered as UI elements so recipe viewers can reposition their overlays", which is an important detail: the screen publishes its occupied rectangles for other mods. Needs: nested tabs, exclusion-zone publication.
- **Botania** (https://botaniamod.net/). Mana bar HUD when holding mana items, wand-of-the-forest HUD showing bound block, in-world text on the Lexica Botania (a Patchouli book). **Immersive Engineering** manual renders multiblock previews as rotating 3D structures; **PneumatiCraft** has a pressure gauge dial widget and info side tabs with wrapped text; **Modular Routers** has module slots that open sub-GUIs with filters and direction pickers; **Integrated Dynamics** has a Logic Programmer with a scrollable operator list, search and value editors per type.

**Primitive list distilled from section 1**: nine-slice panel; slot (real, ghost, filter, output-only, locked); slot grid with arbitrary size; scroll-clipped slot region; virtualised grid; fluid/gas tank with tiled tinted texture and unit tooltip; energy bar; progress bar with direction and mask; sliding side tab with child content; toggle/cycling icon button with per-state sprite and tooltip; face-config widget; number stepper; text field with search hotkey; colour picker swatches; redstone mode toggle; dial gauge; warning/status icon; exclusion zone publication; hold-key tooltip expansion.

## 2. Knowledge and quest UIs

- **Patchouli** (https://vazkiimods.github.io/Patchouli/docs/patchouli-basics/page-types/). Fully JSON-driven books: book -> categories (nested) -> entries -> pages. Default page types are text, image, crafting, smelting, multiblock (interactive rotating 3D preview with a "visualise in world" button), entity (3D entity spinner), spotlight (item with description), link, relations, quest and empty. Templates compose "components" (text, image, item, header, frame, entity, separator, tooltip, custom) with parameters, and rich text supports macros and formatting codes like `$(l:entry)` links and `$(item)` inline icons. Entries unlock via advancements. Needs: data-driven page schema with extension registry, rich text markup with inline icons and links, entity/multiblock 3D viewport widget, bookmark tabs, page flip animation.
- **Modonomicon** (https://klikli-dev.github.io/modonomicon/). Same book/category/entry/page hierarchy but categories have a "node view": entries are nodes on a 2D pannable canvas connected with arrows, Thaumonomicon style. Multiblock definitions in JSON with matcher system and in-world visualisation. Needs: pan-zoom node canvas, arrow connectors, JSON-defined 3D structure preview.
- **GuideME** (https://guideme.appliedenergistics.org/). AE2's guidebook engine: pages are CommonMark Markdown with YAML frontmatter, custom tags embed 3D scenes from structure files with annotations, inline "JEI-style" recipes, item images and cross-links whose tooltips preview the target. Has a live-preview dev mode. Needs: Markdown layout engine (flow text, headings, tables), embeddable custom block elements, 3D scene viewport with camera controls and overlays.
- **FTB Quests** (https://docs.feed-the-beast.com/mod-docs/mods/suite/Quests/Player/Questbook/Navigating/). Chapter list slides in from the left; quests are icons on a pan-zoom canvas (scroll pans, ctrl-scroll zooms), connected with dependency lines; clicking opens a quest panel with tasks and rewards; editors drag quests, paste images onto the canvas, and add chapter text. Built on **FTB Library** widgets (panels, scroll bars, context menus, text fields, a theme file `ftb_quests_theme.txt` for border colours). Needs: infinite pan-zoom canvas, drag to reposition nodes, context menus, themed borders, popup panels.
- **Better Questing** has a similar canvas plus a party panel; **Immersive Engineering Manual** is a code-defined book with rotating multiblock renders and inline recipes; **Akashic Tome** is a tabbed container for other mods' books; **Tinkers' Construct** stations render the tool being built in 3D above the slots, and tooltips compare stats with coloured deltas; vanilla **Advancements** already have a pan-drag tree canvas with tabs and a background texture per tab. **Ponder** (https://github.com/Creators-of-Create/Ponder) plays a real structure in a mini-world with animated instructions, text overlays anchored to blocks, keyframes and scene tags; it is a scripted 3D scene player inside a Screen.

## 3. HUD overlays

- **AppleSkin** (https://www.curseforge.com/minecraft/mc-mods/appleskin). Draws saturation as an overlay on top of the vanilla hunger bar, flashes the food restored by the held item, and adds food values to tooltips. Needs: render at the exact anchor of a vanilla HUD element, layered above it, with access to the same tick/flash timing.
- **Jade / WAILA / HWYLA** (https://jademc.readthedocs.io/). Info panel at a configurable anchor showing the targeted block or entity. Plugins append `IElement`s (text, item icon, progress bar, images) to the tooltip through `IBlockComponentProvider`; `IServerDataProvider` syncs server-only data. Needs: plugin-extensible tooltip element list, panel auto-sizing, anchor presets and a drag-to-position config screen.
- **Xaero's Minimap / JourneyMap**. Circular or square minimap with rotation, waypoint icons with distance labels, in-world waypoint beams and floating labels, fullscreen pannable map. Needs: render-to-texture minimap, world-to-screen projection for labels, fullscreen pan-zoom canvas.
- **Temperature and stat gauges**: Cold Sweat and Tough As Nails add gauges next to hotbar; Botania and Ars Nouveau draw mana bars; ToroHealth draws health bars above entities (world-anchored 2D); Overflowing Bars and Detail Armor Bar restyle vanilla bars; Inventory HUD+ draws inventory, armour durability and potion timers at arbitrary anchors; Better Third Person changes camera not UI; chat mods restyle chat lines and add tabs.
- **Curios / Baubles / Trinkets** (https://modrinth.com/mod/trinkets). Extra equipment slots injected into the vanilla inventory screen. Trinkets defines slot groups (head, chest, legs, feet, offhand, hand, plus custom) and shows them on a side panel that expands when you click a group; Curios adds a button that opens a scrollable column of slots and a render toggle per slot. Both must move alongside the recipe book and are broken by inventory-replacing mods like Inventorio (https://github.com/RubixDev/Inventorio/issues/318). Needs: slot injection into an existing container screen and container menu, layout-aware anchors.
- Vanilla features that mods overlay or replace: boss bars, status-effect icons, scoreboard, crosshair, subtitles. Mods like "Overflowing Bars" and "Better Mount HUD" replace the vanilla renderer for one element; NeoForge exposes this with named HUD layers (`RegisterGuiLayersEvent`, insert above/below a vanilla layer or replace it) and Fabric with `HudRenderCallback` plus `HudLayerRegistrationCallback`.

**Primitives**: anchored HUD element (nine anchors plus offset, scale), ordered HUD layer stack with named vanilla layers to insert above/below/replace, HUD position editor (drag to reposition), world-to-screen anchored labels, render-to-texture panel, plugin-extensible info panel.

## 4. Config, menus and misc screens

- **Cloth Config** and **YACL** (https://docs.isxander.dev/yet-another-config-lib/gui-builder/getting-started). Builder APIs: categories contain groups contain options; option types are boolean, enum cycler, slider, text, colour, list, with description panels that can show images. Both render a scrollable option list with a left category column. **Mod Menu** lists installed mods with icons, badges and a filter field. **Sodium** shows the flat, modern option pages that YACL copies. **Controlling** adds a search field and conflict highlighting to the keybind screen.
- **FancyMenu** (https://www.curseforge.com/minecraft/mc-mods/fancymenu). Pack makers rebuild the main menu with layered elements, animations (frame sequences), custom buttons that run actions, video splash, and hide or move vanilla buttons. It is entirely data-driven and edits vanilla screens in place, which requires enumerating and repositioning existing widgets.
- **Waystones** shows a scrollable, searchable list of named destinations with sort; **Chisel** shows a variation picker grid where each cell is a rendered block; **Cosmetic Armor** adds a toggle button and a second armour column; **Tom's Simple Storage** is another virtualised search grid; **Apotheosis** and **Enchanting Infuser** replace the enchanting screen with sliders and a scrollable enchant list with progress-tinted bars.
- **Ars Nouveau** spell book: a page of glyph icons filtered by search, drag to reorder the spell sequence in a slot row, colour picker for spell particles. **Psi** (https://github.com/VazkiiMods/Psi) spell programmer: a 9x9 grid of piece cells, each piece rendered as an icon with parameter arrows pointing to neighbours, a side list of available pieces with search, and a live stat panel. This is visual programming on a grid. **Hex Casting** (https://hexcasting.hexxy.media/) draws a hex grid of dots in a translucent full-screen overlay; you drag between dots to draw a pattern, previous patterns stay on screen as coloured strokes, and the stack is shown as text at the side. Needs: freehand stroke rendering with line primitives, hit testing on a hex lattice, custom mouse-drag capture.
- **ComputerCraft** renders a terminal grid of coloured characters in a Screen and on in-world monitor blocks (a block-entity renderer draws the same glyph buffer), and turtles have a slot grid plus terminal. **OpenComputers** likewise has pixel and text screens rendered in world. Needs: glyph buffer widget and a shared "draw this UI onto a world quad" path.
- **Chisels & Bits / Little Tiles** draw a 3D sub-block selection overlay in world and a radial tool menu. **WorldEdit CUI** and **Litematica** draw wireframe and translucent structure previews in world, with a placement screen listing schematics and a material list. **MiniHUD** draws info lines at an anchor and shape renderers (spheres, circles, spawn chunks) in world; **Tweakeroo** adds toggles via a scrollable config list.
- **Simple Voice Chat** draws a HUD microphone icon and speaking-player names, plus a radial-ish group screen. **Origins** shows a carousel of large cards with an icon, title, and scrolling description. **Cobblemon** (https://wiki.cobblemon.com/index.php/PC) is the counterexample to the pixel-art norm: the PC has box tabs, wallpapers, sort and filter dropdowns; the summary screen has stat hexagons and move lists; the battle UI has health bars with slide-in animation and a draggable, resizable message log. **Ice and Fire** bestiary is a Patchouli-like book; **Alex's Caves** has a tablet-style codex.

## 5. UI libraries modders use

- **owo-lib owo-ui** (https://docs.wispforest.io/owo/ui/index). Component tree with `FlowLayout` (horizontal or vertical algorithm), `GridLayout`, `StackLayout`, `ScrollContainer`, `Surfaces` for backgrounds (flat colour, outlined, tiled, nine-slice "panel", vanilla translucent, blur), `Sizing` of fixed, content, fill and expand (expand distributes leftover space after other components), `Insets` for margin and padding, `Positioning` relative or absolute, `.animate()` on any property with easing, an XML UI-model format with a schema for IDE autocomplete and hot reload in dev, and a `Component` interface plus `BaseComponent` for custom components. Container screens layer it over slots with `BaseOwoHandledScreen`.
- **LibGui** (https://github.com/CottonMC/LibGui). `WGridPanel` positions children on an 18-pixel slot grid; `WPlainPanel` by pixel; widgets prefixed `W` (button, slider, text field, item slot, scroll panel, tabs, label). Themes are JSON in resource packs, with a dark mode that switches panel and text colours. Screens are described by a `GuiDescription` shared client and server for containers.
- **LDLib** (GTCEu) and **Modular UI** (GT for 1.12) are widget trees with in-game editors and serialisation. **MaLiLib** (masa) provides config option lists, hotkey editing widgets and in-world render helpers used by Litematica, MiniHUD and Tweakeroo. **Cloth Basic Math**, **Cloth Config** and **YACL** are config screen generators. **Blur** and **Satin** add post-process shaders (background blur behind screens) via render events.
- Platform APIs: Fabric `ScreenHandler` and Forge `AbstractContainerMenu` sync slots; `ContainerScreen`/`AbstractContainerScreen` draws them.
- **Injecting into other screens, the critical capability**:
  - Fabric API `ScreenEvents` (https://maven.fabricmc.net/docs/fabric-api-0.97.9+1.21/net/fabricmc/fabric/api/client/screen/v1/ScreenEvents.html): `BEFORE_INIT` and `AFTER_INIT` fire per screen instance, and from them you subscribe to per-screen `beforeRender`, `afterRender`, `beforeTick`, `afterTick`, `remove`, plus `ScreenKeyboardEvents` and `ScreenMouseEvents` (allow/before/after for press, release, scroll). `Screens.getButtons(screen)` is a mutable list to add or remove widgets. Widgets added this way are only auto-rendered if they are buttons; anything else needs a render hook.
  - Forge/NeoForge `ScreenEvent` (https://github.com/MinecraftForge/MinecraftForge/blob/1.19.x/src/main/java/net/minecraftforge/client/event/ScreenEvent.java): `Init.Pre/Post` with `addListener`/`removeListener` and `getListenersList`, `Render.Pre/Post`, `BackgroundRendered`, `MouseButtonPressed.Pre/Post`, `MouseScrolled`, `KeyPressed`, `Opening`, `Closing`, `RenderInventoryMobEffects` (lets mods move the potion effect column). `ContainerScreenEvent.Render.Background/Foreground` gives the panel's left/top so overlays can align to slots.
  - Common users: JEI/REI/EMI draw item lists to the right of any container screen and read "exclusion zones" via a plugin interface so they avoid Sophisticated tabs and Botania guides; Curios adds a button and slots; Inventory Profiles Next and Inventory Sorter add sort buttons beside every chest; Mouse Tweaks intercepts drag over slots; Quark adds chest buttons; Controlling replaces the keybind list widget. When events are insufficient, mods use Mixins to inject into `init`, `render` or `renderBg`.

## 6. Rendering freedom

- **3D in GUI**: `InventoryScreen.renderEntityInInventory` is reused everywhere (Patchouli entity pages, FTB Quests kill tasks, Cobblemon summary, Origins). Tinkers renders a tool model; IE and Patchouli render whole multiblocks with rotation and layer-by-layer slicing; Chisel and Chisels & Bits render block models in cells; Ponder and GuideME render live mini-worlds with cameras.
- **Animated textures**: fluid sprites use vanilla `.mcmeta` animation; Mekanism and Create animate progress via sprite-sheet frames; FancyMenu plays frame sequences.
- **Shaders in GUIs**: rare but present: blur behind screens (Blur, Satin, owo-ui blur surface, vanilla 1.21 menu blur), Hex Casting's stroke glow, Botania's rainbow text via per-character colour.
- **Tooltips**: `TooltipComponent` on the item plus a registered `ClientTooltipComponent` renderer (Fabric `TooltipComponentCallback`, Forge `RegisterClientTooltipComponentFactoriesEvent`, https://maven.fabricmc.net/docs/fabric-api-0.95.3+1.20.5/net/fabricmc/fabric/api/client/rendering/v1/TooltipComponentCallback.html) lets a tooltip contain arbitrary drawn content: vanilla Bundle grid, Shulker Box Tooltip preview grids, map previews, AppleSkin food icons, Jade's elements, Legendary Tooltips rarity frames and borders, Iceberg's tooltip events. Tooltips can be multi-column, contain images, and be positioned away from the cursor.
- **Fonts**: vanilla loads bitmap and TTF fonts from `font/*.json`; Standard Galactic Alphabet (`minecraft:alt`) is used by enchanting; mods add their own fonts (Cobblemon, Create's ponder), and Botania and Hex render glyph strings with custom fonts. Text components carry per-span colour, style and click/hover events.
- **In-world UI**: Create display boards and nixie tubes render text on blocks; Chisels & Bits and Little Tiles draw placement ghosts; IE draws blueprints and multiblock projections; Litematica and WorldEdit CUI draw wireframes; Xaero's waypoint beams and labels; ToroHealth bars; ComputerCraft monitors; Storage Drawers item counts; Hex Casting's grid is itself a world-space overlay. All of these are 2D or 3D content anchored to world positions, drawn either as billboards or on block faces.

## Key takeaways

- **Screen injection is the single most important extension point.** Mods add buttons, slots and overlays to screens they do not own, so the plugin set needs per-screen-type events for init, tick, before and after render, mouse and keyboard, plus a mutable widget list and the panel's origin.
- **Screens must publish their occupied rectangles** so overlays like recipe viewers can avoid side tabs; make exclusion zones a first-class query.
- **A custom widget trait** with measure, layout, draw, input and tooltip hooks is the base everything else stands on; owo-ui's `Component` and LibGui's `WWidget` show the shape.
- **Layout containers matter as much as widgets**: flow, grid, stack, scroll, with sizing modes fixed, content, fill and expand, and insets. Slot-grid alignment on an 18-pixel step is a common special case.
- **Slot behaviour must be pluggable**: ghost, filter, locked and output slots differ in drop handling, not appearance.
- **Virtualised grids with search** are what storage mods live on; support data sources of thousands of entries and variable row counts driven by window height.
- **Tank, energy and progress widgets** are the machine-GUI vocabulary; they need tiled tinted textures, masked fills and unit-formatting tooltips.
- **Sliding side tabs** that grow, host children and animate are the modded look; make tabs a container, not a button.
- **Tooltips are compositional**: a registry of tooltip component types, hold-key expansion, and decoration hooks for frames.
- **A 3D viewport widget** rendering entities, items, blocks, multiblocks and scripted mini-worlds to a texture unlocks books, ponder-style tutorials, tool previews and creature summaries.
- **Data-driven books** need a page-type registry, rich text with inline icons and links, unlock conditions, and ideally Markdown input with embeddable blocks.
- **A pan-zoom canvas** with draggable nodes and connectors serves quests, node-view books, advancement trees and visual programming.
- **HUD needs anchors, a named layer stack and a position editor**, with the ability to insert above or below or replace a built-in layer, and to draw at world-anchored screen positions.
- **In-world UI shares the widget tree**: text on blocks, terminals on monitors, health bars and placement previews should draw the same components onto world quads or billboards.
- **Theming and declarative layouts** (nine-slice sets, dark mode, XML/JSON layouts with hot reload) are what let pack makers restyle everything without code.
