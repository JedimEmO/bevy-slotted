# The Lua API

Generated by `cargo xtask gen-docs` from the `---` doc blocks in
`crates/slotted-script/prelude/slotted.lua` and `slotted_test.lua`. Edit those
files, not this one.

Every function here only builds tables. Nothing in a script reaches the host
directly: a data script emits registrations, a control script answers events with
commands, and the host validates each one before applying it.

Type stubs for luau-lsp are in [`slotted.d.luau`](slotted.d.luau).

### Fields

#### `slotted.api_version`

The API version this host speaks. Compare it against your `mod.toml`
`api_version` if you need to branch on host age.

#### `slotted.mod_id`

Your own mod id, as written in `mod.toml`. Bare ids you pass to any
`register_*` call are namespaced with it.

#### `slotted.stage`

Which stage this chunk is running in: `"data"`, `"control"` or `"test"`.

### Data stage

#### `slotted.register_item(id, def)`

*Stage: `data`.*

Add an item to the registry, or replace one another mod registered.

| Argument | Type | |
|---|---|---|
| `id` | `string` | An item id. A bare `"copper_ingot"` is namespaced with your mod id; `"other:thing"` is taken as written. |
| `def` | `table` | The item def. `display_name` is a locale key, `max_stack_size` a number, `rarity` one of the theme's rarity names, `tags` an array of tag ids, `components` a map of default component values. |

Returns nothing.

```lua
slotted.register_item("copper_ingot", {
    display_name = "mymod.item.copper_ingot",
    max_stack_size = 64,
    tags = { "c:ingots" },
})
```

#### `slotted.register_tag(id, def)`

*Stage: `data`.*

Add a tag, or add entries to one that already exists. Tags merge across
mods, so naming a tag another mod owns extends it rather than replacing it.

| Argument | Type | |
|---|---|---|
| `id` | `string` | A tag id, conventionally in the `c:` namespace for cross-mod tags. |
| `def` | `table` | `values` is an array of item or tag ids; a leading `#` marks a nested tag. `replace = true` discards what other mods put in the tag first. |

Returns nothing.

```lua
slotted.register_tag("c:ingots", { values = { "mymod:copper_ingot" } })
```

#### `slotted.register_recipe_type(id, def)`

*Stage: `data`.*

Add a recipe type. The item browser gives each type its own tab.

| Argument | Type | |
|---|---|---|
| `id` | `string` | The recipe type id. |
| `def` | `table` | `title_key` is the locale key for the browser tab, `size` the `{ cols, rows }` of the crafting grid it draws. |

Returns nothing.

```lua
slotted.register_recipe_type("assembly", {
    title_key = "mymod.recipe_type.assembly",
    size = { 3, 3 },
})
```

#### `slotted.register_recipe(id, def)`

*Stage: `data`.*

Add a recipe.

| Argument | Type | |
|---|---|---|
| `id` | `string` | The recipe id. It does not have to match the result item. |
| `def` | `table` | `recipe_type` names a registered type. A shaped recipe carries `shape` (an array of row strings) and `key` (a map from shape character to an item id or `#tag`); a shapeless one carries `ingredients`. `result` is `{ item = ..., count = ... }`. |

Returns nothing.

```lua
slotted.register_recipe("copper_chest", {
    recipe_type = "mymod:assembly",
    shape = { "iii", "i i", "iii" },
    key = { i = "#c:ingots" },
    result = { item = "mymod:copper_chest", count = 1 },
})
```

#### `slotted.register_fluid(id, def)`

*Stage: `data`.*

Add a fluid, so a `tank` node can name it and paint itself in its colour.

| Argument | Type | |
|---|---|---|
| `id` | `string` | The fluid id. |
| `def` | `table` | `display_name` is a locale key, `color` a `"#RRGGBB"` string, `density` a number (a negative one floats). |

Returns nothing.

```lua
slotted.register_fluid("molten_copper", {
    display_name = "mymod.fluid.molten_copper",
    color = "#C87137",
})
```

#### `slotted.register_hud_layer(id, def)`

*Stage: `data`.*

Add a HUD layer: a small tree drawn over the world rather than inside a
screen. The player can move it with the position editor in dev builds.

| Argument | Type | |
|---|---|---|
| `id` | `string` | The layer id. |
| `def` | `table` | `tree` is a `UiNodeDef` (required). `anchor` is a corner or edge name, `offset` a `{ x, y }` pair, `scale` a number, `visible` a boolean. |

Returns nothing.

```lua
slotted.register_hud_layer("mana", {
    anchor = "bottom_left",
    tree = { type = "bar", property = 0, max = 1, direction = "right",
             tags = { test_id = "mana_bar" } },
})
```

#### `slotted.register_screen(id, tree)`

*Stage: `data`.*

Add a screen. `tree` is a `ScreenDef` body: the same shape a `.screen.ron`
file has, minus the `kind`, which is filled in from `id`.

| Argument | Type | |
|---|---|---|
| `id` | `string` | The screen kind. |
| `tree` | `table` | `root` is the `UiNodeDef` tree; `listring` is the array of inventory indices quick-move walks. See docs/guide/screens.md for every node type. |

Returns nothing.

```lua
slotted.register_screen("chest", {
    root = {
        type = "panel", role = "panel",
        layout = { direction = "column", gap = 2, padding = 2 },
        children = {
            { type = "text", key = "mymod.chest.title", style = "title" },
            { type = "anchor", id = "title_end" },
            { type = "slot_grid", inventory = 0, cols = 9, rows = 3, first = 0 },
        },
    },
    listring = { 0, 1 },
})
```

#### `slotted.register_widget(id, template)`

*Stage: `data`.*

Add a reusable node template. A `custom` node naming this id is replaced by
the template, with its own children spliced into the template's `children`
anchor.

| Argument | Type | |
|---|---|---|
| `id` | `string` | The widget kind other screens name. |
| `template` | `table` | A `UiNodeDef`. Put an `{ type = "anchor", id = "children" }` node where the caller's children should land. |

Returns nothing.

```lua
slotted.register_widget("framed", {
    type = "panel", role = "panel",
    layout = { direction = "column", padding = 1 },
    children = { { type = "anchor", id = "children" } },
})
```

#### `slotted.inject(screen_kind, spec)`

*Stage: `data`.*

Splice a node into a screen at a named anchor, including a screen your mod
does not own. This is the whole extension story: name a screen kind and an
anchor, and the host does the splicing when that screen spawns.

| Argument | Type | |
|---|---|---|
| `screen_kind` | `string` | The screen to patch, or `"slotted:any"` for every screen that has the anchor. |
| `spec` | `table` | `anchor` is the anchor id (required), `node` the `UiNodeDef` to splice in (required), `exclusion = true` publishes the node as an exclusion zone so the item browser keeps clear of it. |

Returns nothing.

```lua
slotted.inject("slotted:any", {
    anchor = "title_end",
    exclusion = true,
    node = { type = "custom", kind = "slotted:button",
             params = { label = "Sort" },
             tags = { my_action = "sort" } },
})
```

#### `slotted.add_tooltip_part(spec)`

*Stage: `data`.*

Add nodes to the tooltip of every stack that matches a filter. Both filters
empty means every stack.

| Argument | Type | |
|---|---|---|
| `spec` | `table` | `nodes` is the array of `UiNodeDef`s to append (required). `items` and `tags` are the filters, `tier` is `"any"`, `"compact"` or `"expanded"`, `id` is a stable id so a hot reload replaces the part rather than adding a second one. |

Returns nothing.

```lua
slotted.add_tooltip_part({
    id = "hunger",
    tags = { "c:foods" },
    tier = "expanded",
    nodes = { { type = "text", key = "mymod.tooltip.hunger", style = "muted" } },
})
```

### Control stage

#### `slotted.on(event_name, handler)`

*Stage: `control`.*

Subscribe to a host event. The handler is called with the event table and
returns nothing, one command table, or an array of them. Several handlers
may share an event; they run in registration order.

A handler must not register anything. Registries are frozen by the time the
control stage runs.

| Argument | Type | |
|---|---|---|
| `event_name` | `string` | One of `slot_click`, `widget_activate`, `tooltip_build`, `recipe_lookup`, `screen_opened`, `screen_closed`, `hud_tick`, `search_changed`, `property_changed`, `control_start`. |
| `handler` | `function` | Called as `handler(event)`. |

Returns nothing.

```lua
slotted.on("slot_click", function(ev)
    if ev.modifiers.alt and ev.button == "left" then
        return slotted.cmd.toggle_favorite(ev.menu, ev.slot)
    end
end)
```

### Commands

#### `slotted.cmd.sort(menu, inventory)`

*Stage: `control`.*

Sort one inventory of a menu. Becomes the same `MenuAction` the built-in
action rail sends, so prediction and the authority see an ordinary click.

| Argument | Type | |
|---|---|---|
| `menu` | `number` | The menu id from the event. |
| `inventory` | `number` | Which inventory within the menu. Defaults to `0`, the container. |

Returns `table`: A command table.

```lua
return slotted.cmd.sort(ev.menu, 1)
```

#### `slotted.cmd.quick_stack(menu, from, to)`

*Stage: `control`.*

Move every stack in `from` that already has a home in `to` across.

| Argument | Type | |
|---|---|---|
| `menu` | `number` | The menu id. |
| `from` | `number` | Source inventory index. |
| `to` | `number` | Target inventory index. |

Returns `table`: A command table.

```lua
return slotted.cmd.quick_stack(ev.menu, 1, 0)
```

#### `slotted.cmd.move(menu, from, to)`

*Stage: `control`.*

Move a stack between two slots, as a plan of ordinary clicks.

| Argument | Type | |
|---|---|---|
| `menu` | `number` | The menu id. |
| `from` | `number` | Source slot index, menu-wide. |
| `to` | `number` | Target slot index, menu-wide. |

Returns `table`: A command table.

```lua
return slotted.cmd.move(ev.menu, ev.slot, 0)
```

#### `slotted.cmd.toggle_favorite(menu, slot)`

*Stage: `control`.*

Mark or unmark a slot as a favourite, which sorting keeps in place.

| Argument | Type | |
|---|---|---|
| `menu` | `number` | The menu id. |
| `slot` | `number` | Menu-wide slot index. |

Returns `table`: A command table.

```lua
return slotted.cmd.toggle_favorite(ev.menu, ev.slot)
```

#### `slotted.cmd.click(menu, action)`

*Stage: `control`.*

Send any click action verbatim. The escape hatch, for the modes the other
commands do not cover.

| Argument | Type | |
|---|---|---|
| `menu` | `number` | The menu id. |
| `action` | `table` | A `ClickAction`, tagged the way the model serialises it. |

Returns `table`: A command table.

```lua
return slotted.cmd.click(ev.menu, { type = "quick_move", slot = ev.slot })
```

#### `slotted.cmd.set_hud(layer, value)`

*Stage: `control`.*

Replace parts of a HUD layer. An unknown layer id creates one on top.

| Argument | Type | |
|---|---|---|
| `layer` | `string` | The layer id. |
| `value` | `table` | Any of `tree`, `anchor`, `offset`, `scale`, `visible`. Whatever you leave out keeps its current value. |

Returns `table`: A command table.

```lua
return slotted.cmd.set_hud("mymod:mana", { visible = false })
```

#### `slotted.cmd.hud_update(layer, path, value)`

*Stage: `control`.*

Write one value into a HUD layer's node, found by its `test_id`. A string
sets text, a boolean sets visibility, a number or a `{ value, max }` pair
sets a fill. Cheaper than replacing the tree every tick.

| Argument | Type | |
|---|---|---|
| `layer` | `string` | The layer id. |
| `path` | `string` | The target node's `test_id`. |
| `value` | `any` | A string, a boolean, a number, or `{ value = n, max = m }`. |

Returns `table`: A command table.

```lua
return slotted.cmd.hud_update("mymod:mana", "mana_bar", { value = 30, max = 100 })
```

#### `slotted.cmd.tooltip(nodes)`

*Stage: `control`.*

Append nodes to the tooltip being composed. Only valid in reply to a
`tooltip_build` event, where the filters of a static part make no sense.

| Argument | Type | |
|---|---|---|
| `nodes` | `table` | An array of `UiNodeDef`s. |

Returns `table`: A command table.

```lua
slotted.on("tooltip_build", function(ev)
    if ev.tier ~= "expanded" then return nil end
    return slotted.cmd.tooltip({
        { type = "text", key = "mymod.tooltip.detail", style = "muted" },
    })
end)
```

#### `slotted.cmd.log(level, message)`

Build a console line as a command, for when you want it ordered with the
rest of a handler's reply rather than emitted immediately.

| Argument | Type | |
|---|---|---|
| `level` | `string` | `"trace"`, `"debug"`, `"info"`, `"warn"` or `"error"`. |
| `message` | `any` | Anything; it is passed through `tostring`. |

Returns `table`: A command table.

```lua
return { slotted.cmd.log("warn", "nothing to sort"), slotted.cmd.sort(ev.menu, 1) }
```

### Logging

#### `slotted.log(level, fmt, ...)`

Write a console line immediately. Extra arguments are formatted into `fmt`
with `string.format`.

| Argument | Type | |
|---|---|---|
| `level` | `string` | `"trace"`, `"debug"`, `"info"`, `"warn"` or `"error"`. |
| `fmt` | `string` | A message, or a `string.format` pattern. |
| `...` | `any` | Format arguments. |

Returns nothing.

```lua
slotted.log("debug", "menu %d has %d slots", ev.menu, 63)
```

#### `slotted.info(fmt, ...)`

`slotted.log("info", ...)`.

| Argument | Type | |
|---|---|---|
| `fmt` | `string` | A message, or a `string.format` pattern. |
| `...` | `any` | Format arguments. |

Returns nothing.

```lua
slotted.info("opened %s", ev.screen)
```

#### `slotted.warn(fmt, ...)`

`slotted.log("warn", ...)`.

| Argument | Type | |
|---|---|---|
| `fmt` | `string` | A message, or a `string.format` pattern. |
| `...` | `any` | Format arguments. |

Returns nothing.

```lua
slotted.warn("sort pressed outside a menu")
```

#### `slotted.error(fmt, ...)`

`slotted.log("error", ...)`. Logging an error does not stop the script; to
fail, call Lua's `error`.

| Argument | Type | |
|---|---|---|
| `fmt` | `string` | A message, or a `string.format` pattern. |
| `...` | `any` | Format arguments. |

Returns nothing.

```lua
slotted.error("recipe %s has no result", id)
```

#### `print(...)`

Print to the script console at info level. Arguments are joined with tabs.
There is no `io` and no real stdout in a sandboxed script; this is it.

| Argument | Type | |
|---|---|---|
| `...` | `any` | Anything; each argument is passed through `tostring`. |

Returns nothing.

```lua
print("loaded", slotted.mod_id)
```

### Tests

#### `slotted.test.test(name, fn)`

*Stage: `test`.*

Register a test. The body runs as a coroutine: every action below yields to
the harness and resumes with its answer, so the test reads as straight-line
code while the app advances frames between the lines.

| Argument | Type | |
|---|---|---|
| `name` | `string` | The test name, as it appears in the report. |
| `fn` | `function` | The body, called with no arguments. |

Returns nothing.

```lua
slotted.test.test("the sort button sorts the player inventory", function()
    slotted.test.open_screen("machine:furnace", "machine")
    slotted.test.click({ test_id = "sorter_sort" })
    slotted.test.settle()
    slotted.test.expect_stack({ role = "slot", tag = { region = "player" }, index = 0 }, "demo:coal", 8)
end)
```

### Actions

#### `slotted.test.open_screen(kind, fixture)`

*Stage: `test`.*

Open a screen over a fixture's inventories. Every test starts here.

| Argument | Type | |
|---|---|---|
| `kind` | `string` | The screen kind, `"mymod:chest"`. |
| `fixture` | `any` | `"empty"` (the default), the name of a fixture the host supplies, or an inline table: `slots` is the array of inventory sizes and `fill` maps `"<inventory>:<slot>"` to `{ item = ..., count = ... }`. |

Returns `table`: `{ menu = <id>, screen = <kind> }`.

```lua
local opened = slotted.test.open_screen("mymod:chest", {
    slots = { 27, 27, 9 },
    fill = { ["0:0"] = { item = "demo:cobblestone", count = 12 } },
})
```

#### `slotted.test.click(loc)`

*Stage: `test`.*

Left-click a node.

A locator is a table with any of these keys, all of which must match:
`role` is a semantic role in snake case (`"slot"`, `"side_tab"`,
`"hud_layer"`), `tag` is a map of tags, `test_id` is the `test_id` tag,
`text` is the displayed text, `widget` is a `namespace:path` widget kind,
`item` matches a slot holding that item, and `index` picks the nth match in
tree order.

| Argument | Type | |
|---|---|---|
| `loc` | `table` | A locator. |

Returns nothing.

```lua
slotted.test.click({ role = "slot", tag = { region = "chest" }, index = 0 })
```

Returns `boolean`.

```lua
slotted.test.expect(slotted.test.is_visible({ test_id = "tooltip" }), "a tooltip appeared")
```

#### `slotted.test.log_contains(text)`

*Stage: `test`.*

Whether any console line so far contains `text`. The way to assert on what
a script logged.

| Argument | Type | |
|---|---|---|
| `text` | `string` | A substring. |

Returns `boolean`.

```lua
slotted.test.expect(slotted.test.log_contains("sorting"), "the handler ran")
```

### Expectations

#### `slotted.test.expect(cond, msg)`

*Stage: `test`.*

Fail the test unless `cond` is truthy. Expectations are plain Lua and do
not yield.

| Argument | Type | |
|---|---|---|
| `cond` | `any` | Anything; `false` and `nil` fail. |
| `msg` | `string` | The failure message. Defaults to `"expectation failed"`. |

Returns nothing.

```lua
slotted.test.expect(count == 3, "three stacks moved")
```

#### `slotted.test.expect_eq(a, b, msg)`

*Stage: `test`.*

Fail the test unless `a == b`, reporting both values.

| Argument | Type | |
|---|---|---|
| `a` | `any` | What you got. |
| `b` | `any` | What you expected. |
| `msg` | `string` | A prefix for the failure message. |

Returns nothing.

```lua
slotted.test.expect_eq(slotted.test.property_of({ test_id = "cook" }).value, 0, "cook progress")
```

#### `slotted.test.expect_stack(loc, item, count)`

*Stage: `test`.*

Fail the test unless a slot holds exactly this. Pass `nil` for `item` to
assert the slot is empty.

| Argument | Type | |
|---|---|---|
| `loc` | `table` | A locator for the slot. |
| `item` | `string` | The expected item id, or `nil` for an empty slot. |
| `count` | `number` | The expected count. Any count matches when omitted. |

Returns nothing.

```lua
slotted.test.expect_stack({ test_id = "output" }, "demo:iron_ingot", 1)
slotted.test.expect_stack({ test_id = "input" }, nil)
```
